# Редакционный гайдлайн вопросов (US-CONT-002)

Этот документ читают редакторы и он же целиком передаётся модели при генерации черновиков (`npm run content:draft`).

## 1. Что такое хороший вопрос

Квиз для компании 2–8 человек на русском языке. Цель — чтобы после игры хотелось сыграть ещё. Хороший вопрос даёт одно из ощущений:

- **I_KNOW_THIS** — «я это знаю, а другие нет»;
- **WHY_DO_I_REMEMBER_THIS** — «почему я помню это спустя 20 лет?»;
- **I_FIGURED_IT_OUT** — «не знал, но догадался»;
- **SHARED_KNOWLEDGE** — общий культурный слой, который знают почти все;
- **HERO_CANDIDATE** — почти наверняка ответит только знаток темы;
- **BRIDGE** — понятно разным поколениям или культурам.

**Guessable лучше obscure.** Сложный вопрос не должен быть просто малоизвестной цифрой. Сложность — это соединение двух известных вещей, сильные неправильные варианты, второй слой известной темы или возможность логически исключить варианты.

## 2. Тон

- Формулировка **серьёзная и нейтральная**, даже если тема — «Фабрика звёзд», рингтоны или Crazy Frog. Юмор возникает из темы, а не из формулировки.
- Нельзя: «кринж», «стыдно признаться», «тупой», «позорный», подмигивания и иронию над темой или над тем, кто её знает.
- Нельзя шуточных вариантов ответа. Все четыре варианта — правдоподобные.

## 3. Структура вопроса

- **Один** однозначно правильный ответ. Если есть хоть одна интерпретация, при которой верен другой вариант, вопрос переписывается.
- Ровно **4 варианта**: A–D. Варианты одного типа и похожей длины; правильный не должен выделяться формой.
- У каждого неправильного варианта указан тип:
  - `PLAUSIBLE` — правдоподобный;
  - `COMMON_MISCONCEPTION` — распространённое заблуждение;
  - `NEAR_MISS` — почти верно (соседний год, похожее имя, второе место);
  - `SAME_CATEGORY` — из той же категории (другой канал, другая группа);
  - `CONTEXTUAL_CONFUSION` — путают по контексту (похожий хит того же года).
- **Explanation** — 1–2 предложения: даёт контекст или любопытную деталь, а не повторяет ответ.
- Текст вопроса — до ~200 символов, читается вслух за 10 секунд.
- Избегать отрицаний («что из этого НЕ…») и формулировок «какое утверждение верно».

## 4. Метаданные

| Поле | Как заполнять |
|---|---|
| `difficulty` 1–5 | Для **целевой аудитории темы**. 1 — знают почти все в ней, 3 — около половины, 5 — только знатоки. |
| `dignity` 1–5 | 5 — история, наука, литература, искусство; 3 — мейнстрим (кино, мировая поп-музыка); 1 — «культурный мусор»: реалити, ринг­тоны, реклама, мемы. **Не связана со сложностью.** |
| `culture_specificity` | `GLOBAL` — понятно в любой стране; `REGIONAL` — у вопроса есть культурный «хозяин», но другие могут догадаться; `LOCAL` — имеет смысл только для своей культуры. |
| `is_bridge` | true, если вопрос связывает поколения или культуры (старая песня в TikTok, ремейк). |
| `contexts` | Культурные контексты с весом 0–1, например `POST_SOVIET: 1.0`. |
| `generations` | Эпохи, когда тема была на пике: `80s`, `90s`, `00s`, `10s`, `current`. |
| `effects` | 1–3 эффекта с весами. |
| `age_safety` | `ALL` по умолчанию; `NON_EXPLICIT_ADULT` — взрослые темы без откровенности; `EXPLICIT_18` — не использовать в MVP. |
| `editor_rating` | Необязательно: насколько вопрос нравится редактору, 1–5 (звёзды в `npm run content:review`). Только для редакции, в игру не попадает. |

## 5. Непереводимость (BR-127)

Вопрос с `culture_specificity: LOCAL` пишется только на «родном» языке своей культуры. Вопросы про постсоветское ТВ, музыку, рекламу существуют только на русском. Не создавать переводы таких вопросов.

## 6. Аудитория 13–17

Темы отношений, знаменитостей и неловкие сюжеты допустимы без откровенных деталей. Не допускаются: откровенный сексуальный контент, натуралистичное насилие, наркотики в положительном контексте.

## 7. Чего избегать в MVP

- Современная политика (после 2000 года), текущие военные конфликты, религия.
- Факты, которые быстро устаревают (рекорды, «сейчас», «самый популярный»). Если это неизбежно — `time_sensitive: true`.
- Вопросы, где ответ — длинное число или точная дата без возможности догадаться.
- Вопросы, ответ на которые можно найти в формулировке.

## 8. Источники и проверка

- У каждого факта ≥ 1 источник. Источники, предложенные моделью, имеют `verified: false` — **ссылка могла быть выдумана**.
- Редактор открывает источник, подтверждает факт, ставит `verified: true`, затем `status: FACT_CHECKED` или `APPROVED` и штамп `reviewed: { by, at }`.
- Сомнения записываются в `review_notes`. Вопрос с непустыми `review_notes` не должен быть APPROVED.

## 9. Пример

```yaml
- id: kukly-channel
  statement: "Программа «Куклы» выходила на телеканале НТВ (1994–2002)."
  sources:
    - { name: "Википедия: Куклы (телепередача)", type: REFERENCE, verified: false }
  questions:
    - id: kukly-channel-ru-1
      language: ru
      origin_language: ru
      culture_specificity: LOCAL
      text: "На каком телеканале выходила сатирическая программа «Куклы»?"
      options:
        - { key: A, text: "НТВ", correct: true }
        - { key: B, text: "ОРТ", distractor: SAME_CATEGORY }
        - { key: C, text: "РТР", distractor: SAME_CATEGORY }
        - { key: D, text: "ТВ-6", distractor: NEAR_MISS }
      explanation: "Программа выходила с 1994 по 2002 год; её прототипом была британская Spitting Image."
      topics: { ru-tv-90s-00s: 1.0 }
      contexts: { POST_SOVIET: 1.0, RUSSIA_1990S: 1.0 }
      generations: { 90s: 1.0 }
      difficulty: 3
      dignity: 2
      effects: { WHY_DO_I_REMEMBER_THIS: 1.0, I_KNOW_THIS: 0.6 }
      status: DRAFT
      generation_method: AI
```
