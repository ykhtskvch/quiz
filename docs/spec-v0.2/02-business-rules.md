# 02 — Business Rules v0.2

> Источник: Business Rules v0.1. Строки, изменённые решениями из [../decisions-v0.1.md](../decisions-v0.1.md), помечены `[D-xx]` / `[T-xx]`. Новые правила — BR-127 и далее.

## 1. Room & Session

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-001 | Игра проводится в рамках временной Room. | При создании Room система создаёт уникальную Room, код подключения и первую Game Session в статусе ONBOARDING. `[D-08]` |
| BR-002 | Для подключения не требуется аккаунт. | Вход только по room code / QR и временному nickname. Email, пароль и регистрация не запрашиваются. |
| BR-003 | Целевой размер группы — 4–8 игроков; минимум для старта — 2. `[D-12]` | Игра корректно работает для 2–8 одновременно подключённых игроков; Start недоступен при < 2 игроках. |
| BR-004 | Один игрок создаёт Room, но не становится обязательным ведущим. | Создатель Room участвует в игре и отвечает на вопросы. |
| BR-005 | Создатель Room получает технические controls. | Доступны Start, Pause, Resume, Skip, End Game. |
| BR-006 | Игра не требует живого ведущего. | После старта система сама показывает вопрос, принимает ответы, показывает reveal и через настраиваемый интервал (10–15 с) переходит к следующему. |
| BR-007 | Игрок может подключиться после начала игры. | Late joiner проходит сокращённый onboarding и участвует со следующего вопроса. |
| BR-008 | Late joiner не получает баллы за пропущенные вопросы. | Total score считается с момента подключения. |
| BR-009 | Игру можно завершить в любой момент. `[D-11]` | После End Game система немедленно формирует leaderboard и статистику. Если текущий вопрос ещё не прошёл reveal, он аннулируется как Skip (BR-087). |
| BR-010 | Целевая продолжительность — около 30 минут. | Фиксированного количества вопросов нет. |
| BR-011 | Около 30 минут система предлагает закончить или продолжить. | Предложение не завершает игру автоматически. |

## 2. Player Identity & Privacy

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-012 | Игрок использует временный nickname. | Nickname существует в пределах Room; дубликаты различаются автоматически. |
| BR-013 | Персональные предпочтения игрока приватны. | Другие игроки не видят его темы, уровень знаний, возрастную группу, культурный бэкграунд, Dignity и негативные предпочтения. |
| BR-014 | Создатель Room не видит onboarding остальных. | Host UI показывает только готовность игроков. |
| BR-015 | Система никогда не раскрывает, для кого подобран вопрос. | На question screen, reveal и в статистике нет attribution «вопрос появился из-за игрока X». |
| BR-016 | Долговременный персональный профиль не создаётся. | В новой Room пользователь снова проходит onboarding. |
| BR-017 | Email и постоянные identifiers не требуются. | Core gameplay полностью доступен без регистрации. |

## 3. Onboarding

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-018 | Каждый игрок проходит onboarding индивидуально. | Onboarding открывается на его устройстве после ввода nickname. |
| BR-019 | Onboarding короткий и визуальный. | Основное взаимодействие — выбор карточек, а не анкета. |
| BR-020 | Игрок выбирает интересующие темы. | Выбранные темы повышают вероятность соответствующих вопросов. |
| BR-021 | Игрок может указать темы, которых хотел бы меньше. | Вероятность темы снижается, но тема не запрещается. |
| BR-022 | Hard No для обычных тем отсутствует. | Ни одна стандартная тема не исключается из-за «less of this» одного игрока. |
| BR-023 | Произвольные категории вручную не вводятся. | Выбор только из контролируемой taxonomy. |
| BR-024 | Игрок указывает приблизительную возрастную группу. | Точный возраст и дата рождения не требуются. |
| BR-025 | Игрок может указать уровень интереса/знаний по теме. | Система различает Casual / Interested / Expert. |
| BR-128 | Игрок может приватно указать культурный бэкграунд. `[D-01]` | Необязательный шаг «С какой культурой ты вырос(ла)?», multi-select карточек контекстов. При пропуске контекст выводится из выбранных тем (например, «Фабрика звёзд» → POST_SOVIET) с пониженной уверенностью. |

## 4. Group Personalisation

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-026 | Квиз строится на агрегированных предпочтениях Room. | При Start Composition Engine получает профили всех игроков, завершивших onboarding; профили late joiners добавляются по мере входа. |
| BR-027 | Интересы большинства не вытесняют интересы меньшинства. | Алгоритм резервирует часть вопросов для менее распространённых интересов. |
| BR-028 | Система стремится создать Hero Moment для каждого игрока. | В подборке есть candidate questions под сильный индивидуальный интерес каждого игрока, если банк позволяет. |
| BR-029 | Hero Moment не обещается публично. | UI не обещает «каждому будет персональный вопрос». |
| BR-030 | В квизе есть wildcard questions. | Не все вопросы соответствуют выбранным интересам. |
| BR-031 | При нехватке контента тематическое кольцо незаметно расширяется. | exact subtopic → parent → related → wildcard, без ошибки для пользователя. |
| BR-032 | Персонализация незаметна. | Квиз выглядит обычной последовательностью без объяснения логики подбора. |

## 5. Language & Cultural Context  `[D-02]`

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-033 | «Режим» игры — это только язык комнаты. | Room имеет один язык (MVP: `ru`). Интерфейс и все вопросы показываются на нём. |
| BR-034 | Культурный микс определяется профилями игроков, а не режимом. | Веса культурных контекстов комнаты рассчитываются из BR-128. |
| BR-035 | Постсоветский контекст — опыт взросления, а не знание языка. | Знание русского само по себе не назначает контекст POST_SOVIET. |
| BR-036 | В одной игре можно смешивать несколько культурных контекстов. | Российское ТВ 90-х, британская культура и международная поп-музыка могут встречаться в одной сессии. |
| BR-037 | Культурный контекст не является раундом. | Вопросы разных контекстов чередуются свободно. |
| BR-127 | Культурно-специфичные вопросы не переводятся. | Вопрос с `culture_specificity = LOCAL` существует только на языке своего контекста (`origin_language`). Перевод (новый QUESTION с тем же fact_id) допустим только для `GLOBAL` или `is_bridge = true`. |
| BR-133 | Культурные различия используются как механика. | Допустимы вопросы, потенциально более лёгкие для человека из определённой культурной среды. |

## 6. Age & Mixed Generations

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-038 | Возраст большинства не определяет возраст всего квиза. | Малочисленная возрастная группа получает релевантные вопросы. |
| BR-039 | Движок создаёт межпоколенческие вопросы. | В игре есть вопросы, понятные нескольким поколениям. |
| BR-040 | Движок может создавать generation-specific Hero Moments. | Подросток и взрослый получают вопросы, где их поколенческий опыт даёт преимущество. |
| BR-041 | При несовершеннолетних explicit 18+ исключается. | В Room с игроком 13–17 не показывается явно сексуальный / графический контент. |
| BR-042 | Подростки не включают «детский режим». | Допустимы слегка провокационные, awkward и low-status вопросы в non-explicit форме. |

## 7. Cultural Dignity

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-043 | Cultural Dignity — отдельное измерение от сложности. | Тема может иметь низкую Dignity и высокую difficulty, и наоборот. |
| BR-044 | Низкая Dignity — полноценный материал квиза. | В банк входят «Фабрика звёзд», Тимати, Crazy Frog, Gangnam Style, reality TV, рингтоны, старая реклама. |
| BR-045 | Вопросы с низкой Dignity формулируются серьёзно. | Комедийные формулировки не добавляются только потому, что тема «низкая». |
| BR-046 | Продукт не маркирует вопросы словами «кринж», «тупой», «стыдный». | Этих слов нет в player-facing UX. |
| BR-047 | Каждый игрок приватно задаёт предпочтение Dignity. `[D-13]` | Три варианта (рабочие формулировки: «больше классики» / «баланс» / «больше поп-культуры и ностальгии») → внутренние 4 / 3 / 2. Room-level значение — медиана. Финальный текст — после UX-теста. |

## 8. Knowledge Experience

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-048 | Вопросы классифицируются по Knowledge Effect. | Metadata хранит I_KNOW_THIS / WHY_DO_I_REMEMBER_THIS / I_FIGURED_IT_OUT / SHARED_KNOWLEDGE / HERO_CANDIDATE / BRIDGE с весами. |
| BR-049 | Движок балансирует Knowledge Effects сам. | Игрок не выбирает доли эффектов. |
| BR-050 | В квизе есть вопросы «WHY DO I REMEMBER THIS». | Используются cultural-memory artefacts. |
| BR-051 | В квизе есть niche expertise questions. | Часть вопросов рассчитана на то, что ответит один участник. |
| BR-052 | Сложность не строится на бессмысленной obscure trivia. | Difficulty сочетается с интересом, логикой, узнаваемостью или культурной ценностью. |

## 9. Difficulty

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-053 | Целевая средняя правильность — 50–70 %. | Selection стремится удерживать aggregate accuracy в диапазоне (мягкая цель, см. Engine §9). |
| BR-054 | В игре разные уровни сложности. | Набор не состоит из вопросов одной difficulty. |
| BR-055 | Допустимы вопросы, на которые ответит только один. | Они не считаются автоматически слишком сложными. |
| BR-056 | Реальная сложность корректируется статистикой. | После достаточного числа игр calibrated difficulty может меняться. До этого действует стартовое правило room difficulty (Engine §8). `[D-07]` |

## 10. Question Format

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-057 | Основной формат — Multiple Choice. | Один правильный ответ и набор distractors. |
| BR-058 | Варианты показываются сразу после presentation phase. | Нет подсказок и отдельной фазы вариантов. |
| BR-059 | Нет betting / risk mechanic. | Баллы не ставятся вручную. |
| BR-060 | Нет обязательных тематических раундов. | Sequence свободно переключается между темами. |

## 11. Question Quality & Distractors

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-061 | У вопроса однозначный правильный ответ. | Неоднозначный вопрос не получает APPROVED. |
| BR-062 | Неправильные варианты — осмысленные distractors. | Типы: PLAUSIBLE, COMMON_MISCONCEPTION, NEAR_MISS, SAME_CATEGORY, CONTEXTUAL_CONFUSION. |
| BR-063 | Шуточный distractor не обязателен. | Вопрос корректен без joke answer. |
| BR-064 | После ответа показывается короткое объяснение. | Explanation даёт контекст, а не повторяет правильный вариант. |
| BR-065 | Вопрос может получить GOLD после подтверждения качества. | Нужны editorial criteria и/или достаточные behavioural signals. |

## 12. Media

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-066 | Модель вопроса поддерживает TEXT, IMAGE, AUDIO, VIDEO. | Media type — часть structured data. MVP: TEXT + IMAGE. |
| BR-067 | Media presentation не уменьшает время на ответ. | Таймер стартует после presentation phase. |
| BR-068 | У каждого media asset есть rights metadata. | Media question не может быть APPROVED без source / licence / rights status. |
| BR-069 | Media с непроверенными правами не используется. | REVIEW_REQUIRED asset не попадает в live game. В MVP — только собственные и public domain изображения. |
| BR-070 | Для media questions предусматривается fallback. | При недоступности media используется alternate asset/text, либо вопрос заменяется до показа. |

## 13. Timing

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-071 | Perception time отделён от answer time. | Озвучка / просмотр media не уменьшают countdown. |
| BR-072 | Базовое окно ответа ≈ 15 секунд. | Значение конфигурируемое. |
| BR-073 | Сложность и media type могут увеличивать окно. | Timer задаётся по metadata (`answer_time_override`). |
| BR-074 | Если все активные игроки ответили — ожидание заканчивается. | Reveal запускается сразу после последнего active answer. |
| BR-075 | Disconnected игрок не блокирует игру. | После timeout (20–30 с) он исключается из active-player count до reconnect. |

## 14. Scoring

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-076 | За правильный ответ — основные баллы. | Неправильный ответ — 0. |
| BR-077 | Скорость даёт бонус. | Более быстрый правильный ответ получает больше. |
| BR-078 | Знание весит заметно больше скорости. | Максимальный бонус существенно ниже base score. |
| BR-079 | Стартовая модель — 1000 + до 150. | Формула конфигурируемая (линейная, см. API §12). |
| BR-080 | Leaderboard не показывается во время игры. | Игрок не видит своё место до End Game. Свои очки за вопрос — видит (US-MOBILE-004). |

## 15. Reveal

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-081 | Reveal — после ответа всех активных или по таймеру. | Оба события завершают answer phase. |
| BR-082 | Reveal показывает правильный вариант. | На shared screen. |
| BR-083 | Reveal показывает объяснение. | Вместе с правильным ответом. |
| BR-084 | Reveal показывает распределение ответов. | Число голосов за A/B/C/D. |
| BR-085 | Reveal не показывает, кто что выбрал. | Individual answers анонимны. |

## 16. Pause, Skip & End

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-086 | Хост может поставить игру на паузу. | Timer и progression останавливаются; при Resume оставшееся время восстанавливается. |
| BR-087 | Хост может пропустить текущий вопрос. `[D-10]` | Skip доступен в PRESENTING и ANSWERING. Все ответы на вопрос аннулируются — никто не получает баллов. fact_id считается использованным. |
| BR-088 | Skip — quality signal. | Skip event записывается для аналитики. |
| BR-089 | Хост может завершить игру в любой момент. | См. BR-009. |

## 17. Reconnect

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-090 | Временный anonymous token восстанавливает игрока. | Refresh / reconnect на том же устройстве восстанавливает nickname и score. |
| BR-091 | Reconnect без email и пароля. | Возврат автоматический через сохранённый token. |

## 18. Duplicate Prevention

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-092 | Вопрос не повторяется в активной Room. | Used question_id исключается. |
| BR-093 | Факт не возвращается в другой формулировке. | Used fact_id исключается. |
| BR-094 | Повтор темы допустим, повтор факта — нет. | Разные факты одной family разрешены, но не подряд. |
| BR-095 | Play Again сохраняет историю вопросов Room. | Новая Game Session исключает ранее использованные fact_id. |
| BR-096 | Между разными Room неповторяемость не гарантируется. | Без аккаунта продукт не помнит прошлые вечера. |
| BR-134 | Показанный вопрос считается использованным. | Presented = consumed, в том числе при Skip. |

## 19. End Game

| ID | Business Rule | Acceptance Criteria |
|---|---|---|
| BR-097 | После End Game — полный leaderboard. | Все игроки ранжируются по очкам. |
| BR-098 | Определяется победитель. | Наибольший score = winner. |
| BR-099 | Показываются 3–5 статистических фактов. `[D-09]` | Hardest Question, Everyone Knew This, Only One Person Knew This, Fastest Correct Answer, Most Divided Question. **Статистика, указывающая на одного игрока через вопрос (Only One Knew), — без имени.** Статистика, не связанная с темой (Fastest Correct), — с именем. |
| BR-100 | Post-game copy не оценивает культурную ценность темы. | Нет «most cringe question/category». |
| BR-101 | Late joiner видит accuracy отдельно от score. | Correct / Attempted. |
| BR-129 | В маленьких комнатах статистика «на одного» отключается. `[D-12]` | При < 4 активных игроках не показываются Only One Knew и аналогичные плашки. |

## 21. Question Bank & AI

## 22. Analytics

| ID | Business Rule | Acceptance Criteria |
|---|---|---|

## 24. Engine-level rules

## 27. Core Acceptance Statement

Система реализует концепцию, если:

1. компания начинает игру без аккаунтов;
2. каждый приватно сообщает интересы и (по желанию) культурный бэкграунд;
3. движок формирует одну общую персонализированную последовательность;
4. предпочтения конкретного человека невозможно определить по UI;
5. игроки отвечают индивидуально с телефонов;
6. вопросы показываются на общем экране;
7. игра смешивает serious knowledge, cultural memory и low-dignity content;
8. разные культурные и возрастные группы получают свои moments of expertise;
9. вопросы и факты не повторяются в активной Room;
10. игру можно закончить в любой момент;
11. победитель показывается только в конце;
12. после игры собирается Play Again Intent.
